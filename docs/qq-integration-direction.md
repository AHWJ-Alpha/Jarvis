# QQ 接入方向：消息插件与界面操作结合

依据本机 `D:\DSHmobile插件\聊天手机\0.3.1\source` 中的 README、index.js 和 napcat.mjs。此文是后续实现方案，当前 APK 尚未包含这个 QQ 适配器。

## 两种方式分别承担什么

| 场景 | 建议方式 | 原因与边界 |
| --- | --- | --- |
| 好友和群消息收发、图片、文件、合并转发 | 适配 DSH 的消息插件架构，通过 NapCat / OneBot 连接 OpenClaw | 有明确的账号、会话、消息 ID 和发送结果，适合后台工作。接口覆盖范围取决于 NapCat / OneBot 版本。 |
| 插件未提供接口的 QQ 页面功能 | 优先使用无障碍节点；节点不可读时使用截图、视觉 / OCR 和点击；需要时由 root 桥执行输入 | 覆盖实际 QQ 界面，但受前台、锁屏、页面变化和弹窗影响，须逐项实现并验证。 |

QQ 空间、语音 / 视频通话、支付及各类小程序等功能不能由“获得 root”推导为已支持，也不能由消息插件的“全 QQ 模式”推导为支持。该模式指自动发现好友及群聊。

## 应复用的设计

1. 按实际登录账号及真实 QQ 号识别机主；机主私聊才进入命令处理，昵称、自称和转发内容不能提升权限。
2. 每位好友、每个群使用独立持久会话；继承全局或工作区人格，不复制机主私人聊天和工具权限。
3. 消息先进入持久收件箱，再分批交给模型。沿用去重、群消息合并、@ 优先、机主优先、暂停和有界重试。
4. 工具显式发送消息并保存回执。超时标为“结果未知”，先核对，避免重复发送。界面操作也需要发送前后核对。
5. 显示真实登录状态、OneBot 连接、待确认 / 扫码、自动回复范围及暂停按钮。登录或账号校验需要时保留人工操作入口。

## 接入 OpenClaw 的具体工作

DSH 插件依赖它的 SessionController、Cordis、模型调用及附件对象，不能直接复制为 OpenClaw 插件。需要把唤醒模型、会话绑定、工具注册、媒体引用和任务完成事件改为 OpenClaw 对应接口，保留消息存储及发送去重语义。普通会话的工具权限应由适配器约束。

先完成状态查询、指定会话读取和受控发送，再接通机主命令与普通会话风格回复，最后增加未被 OneBot 覆盖的界面工作流。以实际功能清单验收，不把“能点击屏幕”等同于“完整 QQ”。

## 单 APK 要求

本机 DSH 的 NapCat 运行在 Termux 的 Debian / LinuxQQ 环境。将来连接现有 OneBot 服务能复用这套消息通道，但会引入对该服务的运行依赖；当前 Jarvis 内置 OpenClaw 并不因此获得 QQ 登录能力。

若要求 QQ 通道也随 Jarvis 单独安装、完全脱离 Termux，则还需另行实现并打包 LinuxQQ / NapCat 的兼容运行环境、登录页面及进程管理，评估体积、设备兼容和后台耗电。界面自动化可以直接操作已安装的官方 Android QQ，也需要逐项实现和验证工作流。两者都不能承诺永久在线或全部页面自动可用。
